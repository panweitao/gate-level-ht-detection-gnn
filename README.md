# Gate-Level Hardware Trojan Detection with GNNs

[简体中文](README_zh-CN.md)

[![DOI](https://img.shields.io/badge/DOI-10.1109%2FTC.2025.3533085-blue)](https://doi.org/10.1109/TC.2025.3533085)
[![License](https://img.shields.io/badge/License-Apache--2.0-green.svg)](LICENSE)

Research code for node-wise hardware Trojan (HT) localization in gate-level netlists using GraphSAGE and GCN models. The pipeline converts standard-cell netlists into graphs, constructs 24-dimensional node features, and classifies every gate as normal or Trojan.

## Method

The released pipeline follows the associated paper:

1. Normalize a gate-level Verilog netlist and extract Trojan-node labels from benchmark metadata.
2. Connect standard-cell instances by matching output nets to downstream input nets.
3. Build a 24-dimensional feature vector for every node:
   - 19-dimensional one-hot standard-cell type;
   - fan-in and fan-out;
   - distance to primary inputs and primary outputs;
   - harmonic centrality.
4. Train a three-layer GraphSAGE model with `mean`, `pool`, `lstm`, or `gcn` aggregation, or train the GCN baseline.
5. Use class-weighted cross entropy to reduce the effect of extreme class imbalance.

## Reported results

| Dataset | Model | TPR | TNR | F1 |
|---|---|---:|---:|---:|
| SAED | GraphSAGE-LSTM | 88.06% | 99.96% | 90.95% |
| LEDA combinational | GraphSAGE-POOL | 88.50% | 99.99% | 92.17% |
| LEDA sequential | GraphSAGE-LSTM | 98.25% | 99.95% | 98.59% |
| EthernetMAC10GE, about 100k gates | GraphSAGE-POOL | 84.62% | 100.00% | 85.24% |

The complete paper-reported summary is stored in [`results/paper_metrics.csv`](results/paper_metrics.csv). These are reported values, not results regenerated by CI.

## Environment

The paper used Python 3.8, PyTorch 1.12.0 with CUDA 11.3, DGL 0.9.1, NetworkX 3.1, and scikit-learn 1.3.0 on an NVIDIA GeForce RTX 2060.

```bash
conda env create -f environment.yml
conda activate gate-ht-gnn
```

Old DGL CUDA wheels may require the archived DGL wheel index. See [`docs/REPRODUCIBILITY.md`](docs/REPRODUCIBILITY.md) before changing framework versions.

## Dataset preparation

Raw SAED and LEDA benchmark files are not redistributed in this repository. Obtain authorized copies from the original benchmark providers, then arrange them as described in [`docs/DATASETS.md`](docs/DATASETS.md).

The generated `.content` format is:

```text
node_id feature_1 ... feature_24 label
```

The `.cites` format is one directed edge per line:

```text
source_node_id destination_node_id
```

Validate prepared data before training:

```bash
python tools/validate_prepared_data.py data/SAED/aftpro_netfeature
```

## Run experiments

Run commands from the repository root.

```bash
# Paper's best SAED model setting
python src/experiments/graphsage_experiments.py \
  --dataset saed \
  --aggregator-type lstm \
  --penalty-scale 0.3 \
  --gpu 0

# LEDA combinational netlists
python src/experiments/graphsage_experiments.py \
  --dataset leda-com \
  --aggregator-type pool \
  --penalty-scale 0.3 \
  --gpu 0

# CPU smoke run; full leave-one-netlist-out training is substantially slower
python src/experiments/graphsage_experiments.py --dataset saed --gpu -1 --n-epochs 1
```

The GCN baseline is available separately:

```bash
python src/experiments/gcn_experiments.py --penalty-scale 0.08 --gpu 0
```

## Reproducibility status

This repository is the cleaned release of the latest implementation from the original experiment workspace. Historical script variants remain in the private research workspace and are not included in this public release. The reported results were reproduced in the original research workflow. Repository CI performs syntax and prepared-data checks rather than repeating GPU training.

Known differences and unresolved provenance items are recorded in [`docs/REPRODUCIBILITY.md`](docs/REPRODUCIBILITY.md) and [`docs/WORKSPACE_AUDIT.md`](docs/WORKSPACE_AUDIT.md).

Structural checks against the original prepared datasets are recorded in [`docs/VALIDATION.md`](docs/VALIDATION.md).
